**Purpose:** Track every Phase 3 initiative, its intended goal, its measurable KPI, and its measured business outcome. Nothing ships in Phase 3 without an entry here — even if the Success Metric is `TBD` at ship time.

**Update cadence:** weekly. See [`./phase-3-roadmap.md#5-cadence`](./phase-3-roadmap.md).

---

## Status legend

Every initiative in §2 carries one of these seven states. Move a row's status forward as the work progresses; never delete rows (cancelled and deferred stay for the audit trail).

- 🟢 **Completed** — shipped **and** Success Metric target reached (or exceeded)
- 🟡 **In Progress** — actively being worked on, **or** shipped and currently measuring toward the Success Metric
- 📋 **Planned** — in the roadmap, not started yet
- ⏸ **Deferred** — pulled from Phase 3, moved to backlog (with a documented reason in Notes)
- 🚫 **Cancelled** — decided not to pursue (with a documented reason in Notes)
- ⚠ **Needs Owner Decision** — blocked awaiting owner input, approval, or a business-side call before it can move
- 🔍 **Under Review** — evaluation in flight (data being collected, options being weighed, decision imminent)

**Column definitions (§2 initiative log):**

- **Initiative** — short action-oriented name.
- **Goal** — qualitative outcome we're moving toward.
- **KPI** — the metric we watch to know if it's working (metric *type* — e.g., `Airbnb tile CTR`).
- **Success Metric** — the concrete measurable business outcome that flips the row to 🟢 Completed (metric *target* — e.g., `+15% CTR within 60 days`).
- **Property** — TW2111 / MS811 / Both / — (portfolio-level or repo hygiene).
- **Platform** — Website / Airbnb / VRBO / Booking.com / Houfy / Off-site / Repo tooling.
- **Status** — one of the seven states above.
- **Notes** — starts with the priority marker (`P1 · …` / `P2 · …` / `P3 · …`) followed by context, blockers, dependencies.

**Reading the columns:**

- **Revenue Impact** — expected annual revenue lift *if* the initiative hits its Success Metric. Portfolio-blended unless the linked §2 row is scoped to a single property. `High (long-term)` means the payoff is meaningful but back-loaded (SEO takes 90+ days to compound).

## 3. Adding a new initiative

When approving a new Phase 3 initiative, add a row to §2 with:

1. **A short action-oriented Initiative name** — *"Airbnb title rewrite"*, not *"Improve Airbnb search visibility"*.
2. **A concrete Goal** — what outcome are we trying to move?
3. **A KPI** — the metric type we watch.
4. **A Success Metric** — the concrete target value with a timeframe (e.g., `≥+15% CTR within 60 days`). If the metric can't be quantified, refine the Goal until it can — or don't add the row.
5. **The affected Property / Platform**.
6. **Starting Status = 📋 Planned** (or 🔍 Under Review if it's genuinely evaluation-first, or ⚠ Needs Owner Decision if blocked on owner input).
7. **Notes column starts with the priority marker** (`P1 · …` / `P2 · …` / `P3 · …`) followed by rationale, blockers, dependencies.

Never delete rows. If an initiative is dropped, mark it 🚫 Cancelled and add the reasoning to the Notes.

If an initiative belongs in the §1 Prioritized Rollup, add it to the rollup table too (top 10 by revenue impact).

## 4. Weekly review agenda (~15 min)

Every Monday during Phase 3:

1. **Move any completed initiatives** to 🟢 Completed **only** after their Success Metric is met. If shipped but still measuring, stay in 🟡 In Progress.
2. **Log the KPI outcome** in the Notes column for any 🟡 In Progress initiative that has enough data (≥14 days post-ship, or a full A/B test cycle).
3. **Promote 🟡 → 🟢** for any Success-Metric-hit initiative.
4. **Flag stalled rows** — any initiative in 🟡 In Progress or 🔍 Under Review that hasn't moved status in 3+ weeks: either bump priority or defer explicitly (⏸ Deferred).
5. **Update Phase 3 §1 outcomes** in [`./phase-3-roadmap.md`](./phase-3-roadmap.md) if any headline number moved.
6. **Refresh the §1 Prioritized Rollup** — if a P2 initiative jumps to P1 (or vice versa), update the ranking table.
